# Support

Start with [installation](docs/installation.md), [CLI help](docs/cli.md),
[troubleshooting](docs/troubleshooting.md) and [FAQ](docs/faq.md).

After the repository is published, use its issue forms for:

- **Bug report:** a minimal reproduction, expected/actual behavior, version and
  operating system, with a short sanitized error excerpt.
- **Feature request:** the task you cannot complete, the desired result and how
  success could be measured.
- **Usage question:** the guide and command you tried and the specific point
  that remains unclear.

Run `agentlean --version` and your interpreter's `--version` to capture versions.
Include the native client version when the problem concerns a launch adapter.
Share only the smallest relevant example. Remove credentials, private project
paths, account information and proprietary data before posting.

Potential vulnerabilities go privately to the [maintainer](MAINTAINERS.md), using
[the security policy](SECURITY.md). Conduct reports follow
[the code of conduct](CODE_OF_CONDUCT.md). Routine support is best kept in public
issues rather than private email. No response-time commitment is established.
