# Governance

AgentLean is maintained by [Bilal Sabugar](MAINTAINERS.md). The maintainer reviews
changes, decides release scope and manages repository access. There is no elected
committee, voting system or separate foundation.

## Decisions

Small fixes can be proposed directly as pull requests. Discuss larger changes in
an issue first, especially provider integrations, new dependencies, schema changes
and behavior that affects permissions, output quality or stored evidence.

Proposals should state the user problem, resulting behavior, compatibility impact
and how the change will be checked. Efficiency claims need measured evidence;
subjective preference alone is not a benchmark. Decisions and relevant tradeoffs
should remain in the issue or pull request.

The maintainer makes the final decision when consensus is unavailable. A decision
can be revisited with a concrete failure case or new evidence. No contribution
size guarantees acceptance or repository access.

## Contributions and releases

Contributors retain ownership of their work and submit changes under the project's
[MIT License](LICENSE). There is no additional contributor agreement or mandatory
sign-off process configured. Do not contribute material you cannot license on
those terms; disclose third-party sources and preserve their notices.

Only authorized maintainers publish releases or grant access. New maintainers are
appointed explicitly by the repository owner based on sustained, responsible
contribution. Release steps are documented in [the release procedure](docs/releasing.md).

This is an early project without a support SLA or guaranteed release cadence.
Project conduct and security concerns follow [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md)
and [SECURITY.md](SECURITY.md).
