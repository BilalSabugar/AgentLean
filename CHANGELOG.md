# Changelog

## 0.4.0

- Open-source guides, maintainer/security contact, governance, community templates,
  validated examples, documentation checks and a clean public-source exporter.
- Fast routing requires explicit acceptance checks; uncertain unvalidated work
  remains on balanced and consequential tasks retain the deep-tier floor.
- Baseline and post-run checks with full on-disk logs and checkpointed evidence.
- Successful native client exits cannot hide failing acceptance checks.
- Optional bounded escalation after validation failure; duplicate presets,
  repeated diagnostics and infrastructure/client errors stop wasted retries.
- Known-red baselines require explicit permission; changed manifests block success.

## 0.3.0

- Optional repository-level model routing with persistent on/off controls.
- User-configured fast, balanced and deep model/effort presets for Codex and Claude.
- Conservative task routing, explicit complexity/risk hints and reported-failure escalation.
- Preview-first native client launcher with per-run on/off override, UTF-8 stdin
  prompts and native exit-code propagation. Existing client permissions are preserved.
- Default-off operation: no personal client settings or already-open chats changed.

## 0.2.0

- Atomic trial-log replacement and OS-backed writer locks that release on exit.
- Managed installation manifests, repeatable installation, explicit upgrades,
  ownership-aware removal and journaled recovery of interrupted operations.
- Native CLAUDE.md integration for the Claude profile; portable explicit loading
  remains available for other clients.
- Strict JSON parsing and persisted identity validation; immutable evidence data.
- Trial-log integrity command and atomic report export with source-log protection.
- Process contention, crash-release, rollback, edit-preservation and recovery tests.
- Isolated wheel lifecycle checks, source distribution, package metadata validation
  and a cross-platform release pipeline.

Version 1 trial records remain readable. Original prototype installs have no
ownership manifest: move their generated workflow file aside before installing
0.2.0. Existing repository instructions remain user-owned and are preserved.

## 0.1.0

Initial local prototype: portable instructions, additive install preview, manually
observed trial logs and descriptive matched-pair reports.
